분석 기능을 새로 만들 필요는 없습니다 — 이미 동작하는 것을 **연결만** 하면 됩니다.

- 화면 경로: `/swing` (회원용 모바일), `/studio` (프로용 PC — 이번 작업 범위 아님)

## 1. 가장 중요한 규칙 — 엔진은 프로토타입에서 수정하지 않습니다

엔진 코드의 **원본은 위 저장소 한 곳**에만 있습니다.
프로토타입에 복사해 넣더라도 **그 파일들은 절대 수정하지 마세요.**

고칠 부분을 발견하면 코드를 직접 손대는 대신, **무엇이 어떻게 잘못됐는지 기록해서 원본 저장소 작업자에게 전달**해주세요.
(예: "가로 모드에서 슬라이더를 끌면 프레임이 안 따라옵니다")

이유: 엔진에는 자동 테스트가 원본 저장소에만 붙어 있고, 나중에 "앱 업데이트 없이 서버에서 엔진만 고치는" 구조로 가려면 원본이 하나여야 합니다. 두 벌로 갈라지면 합치는 비용이 큽니다.

---

## 2. 붙이는 방법 두 가지 — A를 권장합니다

### 방법 A. 웹뷰로 열기 (권장)

앱은 웹뷰 창만 띄우고, 분석 화면은 서버에서 받아옵니다.
**장점: 엔진을 고쳐도 앱을 다시 배포할 필요가 없습니다.** 서버 배포만 하면 전 회원에게 즉시 반영됩니다.

열 주소:

```
https://<사이트주소>/swing                        빈 상태 (사용자가 갤러리에서 직접 선택)
https://<사이트주소>/swing?src=<영상URL>           회원 영상이 미리 로드된 상태
https://<사이트주소>/swing?src=<A>&src2=<B>       비교 모드로 시작
```

- `src`, `src2` 는 **URL 인코딩**해서 넣습니다 (`encodeURIComponent`).
- `<사이트주소>` 는 배포 주소를 넣습니다. 아직 없으면 방법 B로 먼저 진행하세요.

#### 웹뷰에서 반드시 켜야 하는 설정 3가지

이 셋 중 하나라도 빠지면 화면이 동작하지 않습니다.

| 필요한 것 | 안 켜면 생기는 일 |
|---|---|
| **인라인 재생** | 영상이 OS 전체화면 플레이어로 튀어나가고, 그 위에 그린 선이 사라집니다 |
| **파일 선택 처리** | "영상 불러오기"를 눌러도 아무 일도 안 일어납니다 (조용히 실패) |
| **자동재생 제스처 면제** | 재생 버튼을 눌러도 재생되지 않습니다 |

스택별 설정 이름:

- **Android (native WebView)**
  `settings.javaScriptEnabled = true`
  `settings.domStorageEnabled = true`
  `settings.mediaPlaybackRequiresUserGesture = false`
  `WebChromeClient.onShowFileChooser()` 구현 (파일 선택이 여기로 옵니다 — 필수)
  Android 13+ 는 `READ_MEDIA_VIDEO` 권한

- **iOS (WKWebView)**
  `configuration.allowsInlineMediaPlayback = true`
  `configuration.mediaTypesRequiringUserActionForPlayback = []`
  `Info.plist` 에 `NSPhotoLibraryUsageDescription`

- **React Native (react-native-webview)**
  `allowsInlineMediaPlayback`
  `mediaPlaybackRequiresUserAction={false}`
  `allowFileAccess`
  `javaScriptEnabled`

- **Flutter (webview_flutter)**
  `AndroidWebViewController` 에서 `setMediaPlaybackRequiresUserGesture(false)`
  iOS 는 `WebKitWebViewControllerCreationParams(allowsInlineMediaPlayback: true)`

#### 웹뷰 화면 배치

- 분석 화면은 **전체화면 다크 UI**입니다. 앱 헤더·탭바를 겹치지 말고 웹뷰에 화면 전체를 주세요.
- 뒤로가기는 앱 쪽에서 처리하세요 (웹뷰 안에는 뒤로가기 버튼이 없습니다).
- 세로·가로 모두 지원합니다. **가로 회전을 막지 마세요** — 두 영상 비교는 가로가 훨씬 편합니다.

---

### 방법 B. 파일을 프로토타입에 복사 (프로토타입이 React / Next.js 일 때)

서버 없이 프로토타입 안에서 바로 돌려보고 싶을 때 씁니다.

복사할 파일은 **3개**가 전부입니다. 외부 라이브러리 의존성은 **React 하나뿐**입니다.

| 원본 경로 | 역할 | 줄 수 |
|---|---|---|
| `components/swing/SwingAnalyzer.tsx` | 화면 + 동작 전체 | 1471 |
| `components/swing/swing.css` | 스타일 (모든 클래스가 `sw-` 접두사라 기존 CSS와 충돌 없음) | 890 |
| `lib/swing/draw.ts` | 드로잉 엔진 (순수 TypeScript, import 없음) | 278 |

> `lib/swing/sync.ts` 는 PC 스튜디오 전용이라 **복사하지 않아도 됩니다.**

사용법:

```tsx
import SwingAnalyzer from "@/components/swing/SwingAnalyzer";
import "@/components/swing/swing.css";

export default function SwingScreen() {
  return (
    <SwingAnalyzer
      variant="member"                 // 반드시 "member" ("pro"는 PC 스튜디오용)
      initialUrls={[영상URL, 비교영상URL]}  // 없으면 생략하거나 [null, null]
    />
  );
}
```

- 화면 높이를 `100dvh` 로 잡습니다. 부모에 높이 제약을 걸지 마세요.
- `import` 별칭(`@/`)을 쓰지 않는 프로젝트면 상대 경로로만 바꿔주세요. **그 외 코드는 손대지 않습니다.**
- 웹뷰 안에서 돌린다면 위 방법 A의 웹뷰 설정 3가지는 똑같이 필요합니다.
- 페이지 `<head>` 에 다음이 있어야 하단 여백이 맞습니다:
  `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`

## 3. 연동 계약 (이 두 가지만 맞으면 됩니다)

**입력** — 영상 주소를 주는 방법
- 방법 A: URL 쿼리 `?src=`, `?src2=`
- 방법 B: props `initialUrls={[a, b]}`
- 주소를 안 주면 사용자가 화면에서 직접 갤러리에서 고릅니다 (그것도 정상 동작)

**출력** — 없습니다
회원용 분석 화면은 서버에 아무것도 저장하지 않고, 앱에 값을 돌려주지도 않습니다.
회원이 혼자 보면서 분석하는 도구입니다. 그래서 연동이 단순합니다.

**영상 주소 조건**
- 다른 도메인의 영상이면 그 서버가 **CORS** 와 **Range 요청**을 허용해야 프레임 탐색이 부드럽습니다.
- Supabase Storage 서명 URL은 둘 다 지원하므로 그대로 쓰면 됩니다.

## 4. 엔진에 이미 들어 있는 기능 — 다시 만들지 마세요

- 단독 분석 / 2영상 비교 (세로·가로 모두, 두 영상이 가운데 밀착 배치)
- **영상을 탭하면 재생/일시정지** (릴스 방식), 하단에 얇은 슬라이딩바 하나
- 슬라이딩바를 끌면 **프레임이 손가락을 실시간으로 따라옵니다** (저사양 기기까지 검증)
- 배속 0.1 / 0.25 / 0.5 / 0.75 / 1배, 구간 반복
- **두 손가락 핀치로 확대·이동** (어떤 도구를 잡고 있어도 동작), 더블탭 초기화, 좌우 반전
- 드로잉: 실선 · 점선 · 원 · 펜 · 각도(3점 탭, 도수 자동 표시) + 되돌리기 · 전체 지우기
- 도구 레일은 접을 수 있음 (연필 버튼)
- **구간·싱크 편집**: 영상을 좌우로 문질러 프레임 탐색, 시작/끝 핸들을 끌어 두 스윙의 타이밍 정렬

## 5. 붙인 뒤 확인할 것 (체크리스트)

- [ ] 화면이 위아래 잘림 없이 꽉 찬다
- [ ] "영상 불러오기"를 누르면 갤러리가 열린다 ← **웹뷰에서 가장 흔한 실패 지점**
- [ ] 영상을 탭하면 재생되고 다시 탭하면 멈춘다 (전체화면으로 튀어나가지 않는다)
- [ ] 하단 슬라이딩바를 끌면 화면 속 자세가 따라 움직인다
- [ ] 두 손가락으로 확대·이동이 된다
- [ ] 선을 하나 그은 뒤 다시 탭하면 재생된다 (선이 또 그려지지 않는다)
- [ ] "비교"를 켜고 영상 두 개를 열면 좌우로 붙어서 나온다
- [ ] 폰을 가로로 돌리면 가로 배치로 바뀐다

## 6. 수정이 필요하면

### 판정 기준 — 이 질문 하나로 갈립니다

> **"이 수정은 `SwingAnalyzer.tsx` / `swing.css` / `draw.ts` 를 열어야 하는가?"**

- **예** → 프로토타입에서 고치지 말고 원본 저장소 작업자에게 넘깁니다 (아래 형식)
- **아니오** → 프로토타입에서 자유롭게 고칩니다 (웹뷰 설정, 권한, 화면 배치, 감싸는 컨테이너, 라우팅 등)

예외로 **import 경로를 프로젝트에 맞게 상대경로로 바꾸는 것**은 동작이 안 바뀌는 기계적 수정이라 프로토타입에서 해도 됩니다.

### 엔진 문제처럼 보이지만 프로토타입 설정 문제인 것들

아래 증상은 엔진을 뜯어봐도 원인이 없습니다. 전부 웹뷰·레이아웃 설정에서 해결됩니다.

| 증상 | 실제 원인 |
|---|---|
| 영상이 OS 전체화면으로 튀어나가고 그린 선이 사라진다 | iOS 인라인 재생 미설정 |
| "영상 불러오기"를 눌러도 아무 일이 없다 | Android `onShowFileChooser` 미구현 |
| 재생 버튼을 눌러도 재생되지 않는다 | 자동재생 제스처 면제 미설정 |
| 화면 위/아래가 잘린다 | 감싸는 컨테이너 높이 또는 viewport 메타 태그 |
| 하단 슬라이딩바가 안 눌린다 | safe-area 여백, 또는 앱 탭바가 위에 겹침 |
