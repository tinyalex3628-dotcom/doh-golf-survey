# 프로 스윙 영상 넣는 곳

## 1) 파일 넣기
mp4 파일을 이 폴더에 넣습니다. 권장 이름:

| 프로 | 정면 | 측면 |
|---|---|---|
| 이도형 | `lee_fo.mp4` | `lee_dtl.mp4` |
| 김지원 | `kim_fo.mp4` | `kim_dtl.mp4` |

## 2) `src/data/proClips.ts` 에서 4가지를 적기

각 항목마다:

```ts
video: require('../../assets/pro/lee_fo.mp4'),   // ← 주석 풀기
duration: 2.4,                                    // 영상 전체 길이(초)
range: { start: 0.3, end: 1.9, locked: true },    // 스윙 시작~끝(초)
pTimes: [0.3, 0.52, ...],                         // P1~P10 시각(초)
```

- **전부 "영상 시작부터 몇 초"** 단위입니다.
- `pTimes`는 **P1~P10 순서**로 10개. 모르는 구간은 `null`로 두면 화면에서 흐리게 표시되고 눌리지 않습니다.
- `range`는 `locked: true` 유지 — 회원이 프로 영상 구간을 바꾸지 못하게 하는 설정입니다.

## 왜 P구간을 손으로 적나
회원 영상은 AI 자동검출을 쓰지 않기로 했습니다(클럽이 없으면 P2·P6·P8이 원리적으로 안 잡히고,
P3·P5도 검출 실패 시 P4와 같은 프레임으로 뭉개짐). **프로 영상만 운영자가 정확히 지정**해서
학습용 기준으로 쓰고, 회원 영상은 본인이 정한 스윙 시작/끝 구간으로만 봅니다.

## 파일이 없을 때
`video:` 를 주석 처리해두면 앱은 실루엣 + "영상 준비 중"으로 정직하게 표시합니다. 앱은 안 깨집니다.

## 검증 기록 (2026-07-29)
실제 mp4(3.57초·H.264) 1개를 넣고 웹 빌드로 확인한 것:
- Metro가 mp4를 에셋으로 정상 번들 ✅
- `<video>` 생성 + src 연결 ✅

이 개발 환경의 헤드리스 Chromium은 **H.264를 지원하지 않아**(오픈소스 빌드) 실제 픽셀
디코드는 확인 불가였다. 그래서 같은 배선을 **WebM 테스트 영상**으로 끝까지 검증했다:
- 디코드·표시 240×320 ✅ / P칩 클릭 → 영상이 지정한 초로 정확히 이동(0.4·1.0·1.6·2.0s) ✅
- 진행도 슬라이더 25% → 0.747s (구간 0.4~2.0 기준 계산값과 일치) ✅ / 재생 시 시간 흐름 ✅

⚠️ 테스트 중 배운 것: **영상 탐색(seek)에는 서버의 HTTP Range 지원이 필수**다.
`python -m http.server`는 Range를 지원하지 않아 브라우저가 `seekable=[0,0]`으로 보고
탐색이 전부 무시된다(코드 문제로 오인하기 쉬움). 실기기/실서버에서는 정상.
